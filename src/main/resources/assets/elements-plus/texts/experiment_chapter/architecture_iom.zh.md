从这一章开始，我们将正式搭建一台计算机。计算机架构会分成多个章节，每一章实现其中的一部分；在完整架构搭好之前，这些实验都不再关联元件。

计算机执行操作的核心是<font color=blue>指令</font>：一条指令表示一个操作。为了便于书写和阅读，我们用助记符表示指令，例如把 `0011 SS DD` 写成 `MOV D, S`，这就是<font color=blue>汇编</font>。

本章的架构只包含取指、两个通用寄存器、IO 和输出寄存器；还没有 ALU 和数据内存。

**注：计算机架构和信号强度彻底无关——为了方便，这几章节都用 1 来表示任意非 0 的信号强度。**

## 取指与执行

本系列实验的指令由外部的虚拟程序 ROM 提供：

- 你的架构输出 `PC`（8位），作为程序 ROM 的地址；
- 程序 ROM 返回 `INS`（8位），即该地址上的指令字节；
- 架构在当前 tick 内译码并执行 `INS`，在时钟步进时更新寄存器和 `PC`。

取指本身是组合逻辑：`PC -> ROM 地址 -> INS -> 译码`，不需要额外的时钟。虚拟 ROM 由测试系统提供，你不需要搭建；程序 ROM 和数据 RAM 的地址空间也是分开的，本章还没有数据 RAM。

每个 tick 执行一条指令。顺序执行时 `PC` 每 tick 加 1，溢出后回到 0；每个测例开始时 `PC=0`。测试系统会在程序执行完后自动结束测例，所以不需要停机指令。

本章架构的接口：

| 方向 | 信号 | 位宽 | 说明 |
| --- | --- | --- | --- |
| 输入 | `INS` | 8 | 程序 ROM 返回的指令字节 |
| 输入 | `VI` | 1 | 输入数据有效 |
| 输入 | `DI` | 8 | 输入数据 |
| 输入 | `RO` | 1 | 外部准备好接收输出 |
| 输出 | `PC` | 8 | 程序 ROM 地址 |
| 输出 | `RI` | 1 | 电路准备好接收输入 |
| 输出 | `VO` | 1 | 输出数据有效 |
| 输出 | `DO` | 8 | 输出数据 |

## 寄存器

本章只实现两个普通寄存器：

- `R0`（`00`）：8 位累加/通用寄存器；
- `R1`（`01`）：8 位通用寄存器；
- `R2`（`10`）：为后面的内存章节保留，本章测试不会读写它；
- `R3`（`11`）：IO 端口，不是普通寄存器。

`R3` 的读和写都对应外部握手：

- 读 `R3`：从 `DI` 读入数据，同时拉高 `RI` 一个 tick；
- 写 `R3`：把数据写到 `DO`，并让 `VO` 有效，等待外部用 `RO` 取走。

此外还需要一个<font color=blue>输出寄存器</font>，用来保存 `DO` 和 `VO`。它不属于指令集里的 `R0`~`R3`，而是 IO 的一部分：`VO` 保持有效，直到 `RO` 与 `VO` 同时为 1，完成握手后清 0。

## 本章指令：MOV 和 NOP

本章只需要实现两条指令：

- `NOP`：`0000 0000`（`0x00`），什么都不做，只让 `PC` 加 1；
- `MOV D, S`：`0011 SS DD`，把源寄存器 `S` 的值复制到目标寄存器 `D`。

`SS` 和 `DD` 都是 2 位寄存器编号：`00`=`R0`，`01`=`R1`，`10`=`R2`，`11`=`R3`。汇编写作 `MOV D, S`，目标在前、源在后；机器码里先放源 `SS`，再放目标 `DD`。

本章常用的组合：

| 汇编 | 机器码 | 十六进制 | 效果 |
| --- | --- | --- | --- |
| `MOV R0, R1` | `0011 0100` | `0x34` | `R0 <- R1` |
| `MOV R1, R0` | `0011 0001` | `0x31` | `R1 <- R0` |
| `MOV R0, R3` | `0011 1100` | `0x3C` | `R0 <- DI`，拉高 `RI` |
| `MOV R1, R3` | `0011 1101` | `0x3D` | `R1 <- DI`，拉高 `RI` |
| `MOV R3, R0` | `0011 0011` | `0x33` | `DO <- R0`，拉高 `VO` |
| `MOV R3, R1` | `0011 0111` | `0x37` | `DO <- R1`，拉高 `VO` |
| `MOV R3, R3` | `0011 1111` | `0x3F` | `DI -> DO`，同时处理 `RI`/`VO` |
| `MOV R0, R0` | `0011 0000` | `0x30` | 空操作 |
| `MOV R1, R1` | `0011 0101` | `0x35` | 空操作 |

`R2` 相关的组合在本章保留，测试不会使用；你的译码器可以忽略它们。

实现上，`PC` 是一个 8 位寄存器，输出当前地址；`INS` 进入译码器。译码器根据 `INS` 的高 4 位区分 `MOV`/`NOP`，再根据 `SS`/`DD` 选择源和目标：`R0`/`R1` 各有写使能，`R2` 本章不接，`R3` 的读写走 IO 握手。本章不使用的其他编码按 `NOP` 处理即可。

## R3 的读写规则

**读 `R3`（`MOV 目标, R3`）**：

- 如果 `VI=1`，说明输入数据有效：拉高 `RI` 一个 tick，在时钟步进时把 `DI` 保存到目标寄存器；
- 如果 `VI=0`，没有数据可读：本次 `MOV` 被忽略，目标寄存器不变，也不拉 `RI`。

**写 `R3`（`MOV R3, 源`）**：

- 如果 `VO=0`，输出空闲：把源数据写入输出寄存器，`VO` 在下一 tick 变为 1；
- 如果 `VO=1` 且 `RO=0`，输出堵塞：本次写被忽略，`DO`/`VO` 不变；
- 如果 `VO=1` 且 `RO=1`，本 tick 完成握手、`VO` 优先清 0；本次写会等到下一 tick 才生效。

**`MOV R3, R3`**：

- 如果 `VI=1` 且输出不堵塞，直接把 `DI` 送到 `DO`，同时拉高 `RI`，`VO` 在下一 tick 变为 1；
- 如果 `VI=0` 或输出堵塞，整条指令被忽略，不拉 `RI`，也不改变输出。

## 一个简单程序

下面的程序把输入读入 `R0`，再写到输出：

```text
NOP
MOV R0, R3      ; 0011 1100，读输入
MOV R3, R0      ; 0011 0011，写输出
NOP
```

本章还没有跳转指令，所以程序只能顺序执行，不能循环等待 `VI`/`VO`。测试程序会按固定时序提供输入和 `RO`，必要时可以用 `NOP` 对齐。等后面加入跳转后，就可以用等待循环处理不确定的输入/输出时机。

每个测例开始时，`PC`、`R0`、`R1` 和输出寄存器都应为 0。

```epp-experiments
elements-plus:architecture_iom
```

本实验仍然不关联元件。
