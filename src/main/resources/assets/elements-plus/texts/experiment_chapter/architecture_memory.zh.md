前两章的架构只能在寄存器、立即数和 IO 之间操作，还不能保存大量数据。本章给 `R2` 连接一块 256 字节的 RAM，让计算机可以保存和读取数据。本章仍然没有 ALU，只增加数据内存。

程序 ROM 仍然是外部的，由 `PC` 取指；本章新增的是**数据 RAM**，由 `R1` 寻址、`R2` 读写。程序 ROM 和数据 RAM 的地址空间是分开的，`PC` 不会访问数据 RAM。

## 接线

RAM 使用<font color=gold>多字节存储器</font>章节中搭建的<font color=gold>256字节随机存取存储器</font>，其引脚定义如下：

- `D`（8位）：地址输入；
- `A`（8位）：数据输入；
- `WE`（1位）：写选通；
- `Y`（8位）：数据输出。

连接方式：

- `R1` 的 8 位输出接到 RAM 的 `D`（地址输入）；
- 写 `R2` 时，写入的数据接到 RAM 的 `A`，并让 `WE=1`；
- 读 `R2` 时，让 `WE=0`，把 RAM 的 `Y` 选为读出的数据；
- RAM 的读是组合逻辑，写发生在时钟步进时。

因此 `R2` 不是一块独立的寄存器，而是“当前 `R1` 指向的内存单元”的映射。`R1` 一变，`R2` 对应的单元就变了。

## 先设地址，再读写

访问内存的步骤是固定的：

1. 用 `LDL`/`LDH`（或 `MOV`）把地址写入 `R1`；
2. 再对 `R2` 做 `MOV`：
   - `MOV R0, R2`：读 `mem[R1]` 到 `R0`；
   - `MOV R2, R0`：把 `R0` 写入 `mem[R1]`。

例如把 `0x5A` 写到地址 `0x20`，再读回来：

```text
; R1 = 0x20
LDL R1, #0x0    ; 0x50
LDH R1, #0x2    ; 0x92

; R0 = 0x5A
LDL R0, #0xA    ; 0x4A
LDH R0, #0x5    ; 0x85

MOV R2, R0      ; 0x32，mem[0x20] <- 0x5A
NOP
MOV R0, R2      ; 0x38，R0 <- mem[0x20]
MOV R3, R0      ; 0x33，输出 0x5A
```

如果先读写、后设地址，访问的就是旧的 `R1` 指向的单元。地址必须在访问前准备好，并在访问期间保持稳定。

## 为什么 R2 不能用立即数

`R2` 是 `mem[R1]` 的映射，不是独立寄存器。`LDL R2, #n` 如果被允许，语义会变成：

1. 先读出 `mem[R1]`；
2. 修改它的低 4 位；
3. 再写回 `mem[R1]`。

这需要一次内存读和一次内存写，而且会改变内存内容；它不再是“设置寄存器的一半”，而是一条复杂的读—改—写指令。为了保持指令简单，`LDL`/`LDH` 的 `RR=10` 编码被保留，基础架构按 NOP 处理。

如果要把常数写进内存，正确做法是先把常数装入 `R0`，再 `MOV R2, R0`。`R2` 本身没有独立的存储，不能像 `R0`/`R1` 那样保留半个字节。

同理，`R3` 仍是 IO 端口，不能用立即数；这一点在上一章已经说明。

## 译码与写回

在本章，`MOV` 的源/目标选择需要增加 `R2` 路径：

- `R2` 作为源：读出的数据来自 RAM 的 `Y`，而不是普通寄存器；
- `R2` 作为目标：写使能接到 RAM 的 `WE`，写入数据接到 RAM 的 `A`；
- `MOV R2, R2` 没有实际效果，可以按空操作处理；
- 写 `R2` 时，源可以是 `R0`/`R1`/`R3`；如果源是 `R3`，会先完成输入握手，再把读到的数据写入内存。

RAM 的写只应在 `MOV` 的目标是 `R2` 时有效；其他指令必须让 `WE=0`，避免误写。

## 注意

- RAM 的内容只在电路运行时有效，复位或断电后丢失；测试程序会先写入再读取。
- `R1` 是数据地址，`PC` 是程序地址，两者互不影响。
- 本章没有新增指令，仍然使用 `MOV`、`LDL`、`LDH` 和 `NOP`。
- 本章还没有跳转，程序按 `PC` 顺序执行；需要访问多个地址时，逐个用 `LDL`/`LDH` 设置 `R1`。
