在开始搭建计算机架构之前，我们先来做个小实验，用电路真正解决一次问题，同时熟悉输入输出的概念。

本次实验你需要通过输入/输出和测试系统交互，从外部输入两个数字，把它们相加，然后输出。

在实际应用中，我们通常不能立即拿到输入数据，输出的数据也不一定能被立刻处理，因此我们需要一种阻塞式的输入输出约定，即输入数据未就绪时，电路需要等待，输出数据未就绪时，电路也需要等待。

本章采用<color=blue>同拍传输</color>：输入侧的 VI/RI 或输出侧的 VO/RO 同时非 0 的那一拍完成传输，D 必须在该拍有效，不能等下一拍再给。

---

具体来说，当输入就绪时，外部会拉高 VI，并把数据放在 DI 上；在 VI 有效期间，DI 保持不变。如果电路准备好接收，就拉高 RI。VI 和 RI 同时非 0 的那一拍就是<color=blue>传输拍</color>：电路在这一拍的时钟步进时把 DI 保存到寄存器。传输完成后，外部才会更换 DI；如果暂时没有下一个数据，VI 会撤销。

当电路准备好输出时，拉高 VO，并把数据放在 DO 上；在 VO 有效期间，DO 保持不变。外部准备好接收时会拉高 RO。VO 和 RO 同时非 0 的那一拍就是<color=blue>传输拍</color>：外部会在这一拍的时钟步进前读取 DO。传输完成后，电路才可以撤销 VO 或更换 DO。

本次实验涉及到的输入输出有：

---

输入：

- VI（1位）：表示有数据待读取
- RO（1位）：表示准备好读取电路输出
- DI（8位）：输入数据。VI 有效期间保持不变；VI 与 RI 同时非 0 的传输拍，电路应在时钟步进时把 DI 保存到寄存器，之后使用保存的值。

输出：

- VO（1位）：表示有数据要输出
- RI（1位）：表示电路准备好接收输入
- DO（8位）：输出数据。VO 有效期间保持不变；VO 与 RO 同时非 0 的传输拍，外部会在时钟步进前读取 DO。

---

输入数据不一定立刻就绪，因此你的电路需要等待 VI 有效。

下文中说的 V 和 R，输入侧指 VI 和 RI，输出侧指 VO 和 RO。

只有 VI、RI 同时非 0 时，DI 才会被真正读入；同样，只有 VO、RO 同时非 0 时，DO 才会被真正读出。D 必须在这个<color=blue>传输拍</color>已经有效，不能等下一拍再给。

**注意**：同一 tick 只要求 D 在传输拍有效，并不要求你在这一拍算出结果。你可以先等待数据、用多个 tick 计算，准备好后再拉高 RI 或 VO；但在 V 和 R 同时非 0 之后，D 不能再延迟一拍。

对输入，如果 VI=1 而 RI=0，外部会保持 DI 不变；对输出，如果 VO=1 而 RO=0，电路应保持 DO 不变。只有 V 和 R 同时非 0 的那一拍才完成传输。

时钟步进就是采样时刻：DI 在步进前保持稳定，步进时被电路采样；DO 在步进前被外部读走，步进后电路才可以改变它。

例如输入侧：第 5 tick 时 VI=1、RI=1、DI=42，电路在第 5 tick 的时钟步进时保存 42，第 6 tick 起可以使用保存值；外部在第 5 tick 的步进之后才会把 DI 换成下一个数。

输出侧同理：第 8 tick 时 VO=1、RO=1、DO=42，外部在第 8 tick 的时钟步进前读走 42；第 8 tick 的步进之后，电路才可以撤销 VO 或更换 DO。

因此你可以自行决定何时准备好接收输入、何时准备好输出结果，但是不能无限期等待；本实验的测例有时间限制。

为此，我们又引入了一个新的测例失败原因：

- <color=light_purple>TLE (Time Limit Exceeded)</color>：超出测例允许的最大tick数

每个测例你都需要在 20 tick 内完成输出。测例保证两个输入数据在 10 tick 内就绪；你的 VO 有效后，外部保证在 2 tick 内拉高 RO。一旦输出，外部会立即判定输出是否正确，然后进行下一个测例。

```epp-experiments
elements-plus:a_plus_b
```

本次实验将不再关联元件。

20 tick 其实已经相当宽松，理论上最快可以在 2 tick 内完成输入输出——第一个 tick 读取第一个数，第二个 tick 读取第二个数并输出结果。不过这样将无法验证电路的阻塞式输入/输出。

该实验会立即准备好输入和输出，你不需要等待任何数据。因此 VI 在两个 tick 内都为 1，第 2 个 tick VO 也应该为 1。保证第 2 tick（即 VO 为 1 的同一 tick）RO 为 1。

elements-plus:a_plus_b_extreme
