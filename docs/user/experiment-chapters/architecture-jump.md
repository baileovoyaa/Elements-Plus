> 前置章节：[计算机架构——运算](architecture-compute.md)

到上一章为止，`PC` 每个 tick 都只加 1，程序只能从头到尾顺序执行。本章加入<font color=blue>跳转</font>，让程序可以循环、分支，也可以等待输入/输出。

取指接口与上一章相同：`PC` 输出到虚拟程序 ROM，`INS` 输入指令；架构仍然每 tick 执行一条指令。

## 跳转目标寄存器

8 位指令里没有空间直接放下一个 8 位地址，所以跳转不把目标写在指令里，而是先写进一个独立的 8 位寄存器 `TR`（跳转目标寄存器）。

- `SETTARGET Rs`：`1110 00RR`，把寄存器 `Rs` 的值写入 `TR`；
- `Rs` 可以是 `R0`、`R1`、`R2`；`R3` 是 IO，编码保留；
- `SETTARGET R0` = `0xE0`，`SETTARGET R1` = `0xE1`，`SETTARGET R2` = `0xE2`；`SETTARGET R3` = `0xE3` 保留；
- `SETTARGET R2` 读取 `mem[R1]`，可以用来做跳转表；
- `TR` 在时钟步进时更新，下一 tick 的跳转就能使用新值。

所有跳转都执行：

```text
if 条件成立: PC <- TR
else:        PC <- PC + 1
```

`SETTARGET` 本身不改变 `PC`，只设置目标；真正跳转的是后面的 `JMP` 或条件跳转。

## 跳转指令

`JMP` 是无条件跳转；其余指令在条件成立时跳到 `TR`。

| 汇编 | 十六进制 | 条件 |
| --- | --- | --- |
| `JMP` | `0xC0` | 无条件 |
| `JZ` | `0xC1` | `R0 == 0` |
| `JNZ` | `0xC9` | `R0 != 0` |
| `JN` | `0xC2` | `R0 < 0`（有符号） |
| `JNN` | `0xCA` | `R0 >= 0`（有符号） |
| `JP` | `0xC3` | `R0 > 0`（有符号） |
| `JNP` | `0xCB` | `R0 <= 0`（有符号） |
| `JEQ` | `0xC4` | `R0 == mem[R1]` |
| `JNE` | `0xCC` | `R0 != mem[R1]` |
| `JLT.U` | `0xC5` | `R0 < mem[R1]`（无符号） |
| `JGT.U` | `0xC6` | `R0 > mem[R1]`（无符号） |
| `JGE.U` | `0xCD` | `R0 >= mem[R1]`（无符号） |
| `JLE.U` | `0xCE` | `R0 <= mem[R1]`（无符号） |
| `JLT` | `0xE4` | `R0 < mem[R1]`（有符号） |
| `JGT` | `0xE5` | `R0 > mem[R1]`（有符号） |
| `JGE` | `0xE6` | `R0 >= mem[R1]`（有符号） |
| `JLE` | `0xE7` | `R0 <= mem[R1]`（有符号） |
| `JVI` | `0xD0` | `VI == 1` |
| `JNVI` | `0xD8` | `VI == 0` |
| `JVO` | `0xD1` | `VO == 1` |
| `JNVO` | `0xD9` | `VO == 0` |

关于大小比较：

- `JN`/`JP`/`JNN`/`JNP` 把 `R0` 按 8 位补码解释，只与 0 比较；
- `JLT.U`/`JGT.U`/`JGE.U`/`JLE.U` 与 `mem[R1]` 按**无符号** 8 位比较；
- `JLT`/`JGT`/`JGE`/`JLE` 与 `mem[R1]` 按**有符号补码**比较；
- `JEQ`/`JNE` 是相等比较，不区分符号。

处理地址、长度这类非负数时用无符号版本；处理可能为负的值时用有符号版本。

## 设置跳转目标

跳转目标要先放进一个寄存器，再 `SETTARGET`。例如要跳到地址 `0x1A`：

```text
LDL R0, #0xA    ; 0x4A
LDH R0, #0x1    ; 0x81，R0 = 0x1A
SETTARGET R0    ; 0xE0，TR = 0x1A
JMP             ; 0xC0，PC = TR
```

在汇编里会用标签表示地址；实际程序里要把目标地址拆成低 4 位和高 4 位，用 `LDL`/`LDH` 装入寄存器。后面的汇编章节会介绍如何用标签和伪指令简化这些写法。

准备目标会占用一个寄存器（注意不是 `SETTARGET` 指令本身修改了源寄存器）：

- 要把目标地址装进 `R0`，会覆盖 `R0` 里原来的值；
- 装进 `R1`，会覆盖地址寄存器；
- 也可以把目标放在内存，用 `SETTARGET R2` 读取；这不会覆盖通用寄存器，但要求 `R1` 已经指向目标表。

`SETTARGET Rs` 只把 `Rs` 复制到 `TR`，不会修改 `Rs` 本身。因此通常的写法是：**先准备并设置 TR，再准备比较值/数据**；如果数据已经算好，先存到内存，或改用另一个寄存器装目标。

## 等待输入

`JNVI` 在 `VI=0` 时跳转，可以用来等输入有效。假设 `wait_vi` 这段循环的地址是 `0x1A`：

```text
; 先把 wait_vi 的地址 0x1A 装入 R0 并设为 TR
LDL R0, #0xA    ; 0x4A
LDH R0, #0x1    ; 0x81，R0 = 0x1A
SETTARGET R0    ; 0xE0

wait_vi:
    JNVI            ; 0xD8，VI=0 时跳回 wait_vi
    MOV R0, R3      ; 0x3C，VI=1 时读入 DI，并拉高 RI 一个 tick
```

`VI=0` 时，`JNVI` 把 `PC` 设回 `TR`，下一 tick 继续检查；`VI=1` 时条件不成立，顺序执行下一条 `MOV`。`MOV` 会在同一 tick 拉高 `RI`，把 `DI` 读入 `R0`。

如果 `R0` 里已有要保留的数据，可以改用 `R1` 装目标，或把目标放在内存用 `SETTARGET R2`，也可以先把数据存到内存。

## 等待输出

`JVO` 在 `VO=1` 时跳转，可以用来等上一次输出被 `RO` 取走。假设结果在 `R0`，`wait_vo` 这段循环的地址是 `0x24`：

```text
; R0 保存要输出的结果；R1 暂用于设置目标
LDL R1, #0x4    ; 0x54
LDH R1, #0x2    ; 0x92，R1 = 0x24
SETTARGET R1    ; 0xE1

wait_vo:
    JVO             ; 0xD1，VO=1 时跳回 wait_vo
    MOV R3, R0      ; 0x33，VO=0 时写输出
```

`VO=1` 表示上一笔输出还在等待 `RO`；`JVO` 会一直循环到它被取走。`VO=0` 时条件不成立，执行 `MOV R3, R0`，把结果写入输出寄存器，下一 tick `VO` 变为 1。

如果 `R1` 还要用来保存数据地址，可以先把结果存到 `mem[R1]`，再用 `R0` 设置目标，最后输出 `mem[R1]`。

`JVO`/`JNVO` 采样的是执行阶段的 `VO`；如果同一 tick 正好发生 `VO && RO` 握手，`VO` 会在时钟沿被清掉，但本条跳转仍然使用清掉之前的值，所以可能会多循环一次，下一次就会退出。

## 注意

- 跳转目标来自 `TR`，不是指令里的立即数；循环通常只需要在循环外设置一次 `TR`。
- `SETTARGET` 在时钟步进时更新 `TR`，下一 tick 才可见；紧跟其后的跳转使用新值。
- 条件跳转只比较 `R0` 和 0、`R0` 和 `mem[R1]`，或者检查 `VI`/`VO`；没有 flags。
- 本章还没有调用/返回和栈；跳转只能靠 `TR` 和条件完成。
- 条件跳转可能向前或向后，`PC` 不再单调；测试程序会用循环和分支来验证。
