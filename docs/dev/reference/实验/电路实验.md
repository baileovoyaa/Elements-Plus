## 电路实验

电路实验（`CircuitExperiment`）由多个测例组成，进行实验时需要按顺序运行每个测例，一个测例运行完后再运行另一个测例。不要在一个tick中连续运行多个测例（以减轻服务器负担）。

预检时检查：

- 检查物品是否是 **未编译** 的电路图
- 是否包含所有需要的输入和输出标签（可以有多余的，测试时多余的输入全部设为0）
- 测例中包含的输入和输出标签都唯一对应一个元件，没有多个输入/输出元件共用标签的情况（非测例包含的输入/输出不影响），也没有把输出标签填到输入元件上这种情况
- 不存在组合环路

预检不通过要在 `statusButton` 显示为 `error` 状态，并在悬停提示显示具体原因。例如：

```
预检不通过
- 缺少输入标签：A B
- 缺少输出标签：Y
```

每执行完一个测例，如果执行成功，则将对应的 `TestCaseWidget` 的 `color` 设为绿色，并将中间文本设为 `正确`；如果执行失败，中止实验并将对应的 `TestCaseWidget` 的 `color` 设为红色，并将中间文本设为 `错误`。

全部执行完成后，实验成功。通常会编译电路图（取决于实验是否具有 `circuitComponent`）。

## `ConstantCombinationalTestCase`

一个测例只运行1tick。每个测例会设置输入元件的值（与实验无关的输入元件全部置0），并在 **服务端** 进行一次组合求值，判断对应输出元件的值是否符合要求。

`ignoreAnalog` 字段表示是否忽略输出信号强度（只关心0和非0）。

- 如果 `ignoreAnalog` 为 `true`，则信号强度不被考虑在内。此时如果预期值为非0，实际值也为非0即可，而对具体信号强度没有要求。
- 如果为 `false` 则严格比较信号强度。

一旦输出不符合要求，就使实验失败，不再继续执行后续测例。`statusButton` 悬停提示写明具体测例信息。例如：

```
测试不通过
- 输入：A=0, B=1
- 预期输出：S=1, C=0
- 实际输出：S=1, C=1
```

## 随机测例

这种测例每次运行的值不固定。

注意：随机数在测例运行时动态生成，每次运行可能都不同，不要在静态初始化时生成随机数。

> 8位加法器的测例一共有256个，可以参考[8位加法器测例生成.py](../实验/电路/8位加法器测例生成.py)的生成逻辑。对于每个测例，都会对每个输入非0位随机一个1~15的值，以确保电路正确处理了信号强度。

## 时序测例

时序逻辑每个测例将进行多个tick，而非一个tick一个测例。每个tick步进一次电路时钟。测例运行时，测例信息显示“Running”，蓝色背景（加法器章节提到过）。

每个测例是相互独立的，新的测例开始时复位，而不是延续上一个测例的状态。

触发器章节每一个tick都要严格匹配输出，一旦有一个tick不匹配，就会导致测例失败。

失败后，`statusButton` 悬停信息只显示直接导致实验失败的那一tick输入输出，并加一行提示“点击查看完整测例数据”

点击后显示一个对话框（类似 `ToolboxDialog`），有一个可滚动的表格，格式如下（列需要对齐，这里只作演示）：

```
tick 输入T 预期Q 实际Q
0 0 0 0
1 15 0 0
2 15 15 15
3 0 0 15（红色）
```

截断到失败行。实际输出错误的显示为红色，正确的显示为绿色（覆盖一位显示的灰色）。

对于tick数确定的时序测例，测试通过后，测例信息文本 `bottomText` 显示“12 ticks”，失败则显示“10/12 ticks”（表示进行到第11tick时失败）。

## 架构测例

测例程序要调用NOP和一系列MOV指令，使用不同的数据，并且验证没有输入、输出堵塞、MOV R3, R3等情况，以确保电路正确处理了这些

由于是固定每tick执行一条指令，因此每tick外部输入输出基本是确定的，可以使用普通时序测例的变种

PC和INS在测试时会连外部ROM，存在潜在的组合环（如INS直连PC），这个要在预检时发现。

失败测例对话框增加一列，是当前的INS对应的汇编（如MOV R0, R3）

由于输入输出较多，只需包含这些列：

```
tick PC INS 汇编 VI RI DI VO RO DO
```

不需要区分“预期输出”和“实际输出”

并且总线不需要展开每个通道信号强度

tick用白色，测试输入使用灰色，和普通测例一样

正确的输出使用绿色，错误的输出使用红色且后面加括号带绿色预期输出

对话框添加一个“复制程序”按钮，以空格分隔格式复制当前测例已经执行过的ROM内容（从开始到失败tick的程序字节，便于后续粘到ROM里手动调试）

跳转章节由于PC不是线性的，tick数和程序长度可能并不相同，所以跳转章节实验的复制按钮是复制整个测例的程序内容（而不是只有执行到的）

未引入的指令不测，因此能过后面章节的放前面章节测可以通过（但是之前章节的指令可包含，例如立即数及后面的章节可以用MOV），不依赖未定义的NOP行为

跳转章节由于PC不是线性的，tick数和程序长度可能并不相同，所以跳转章节实验的复制按钮是复制整个测例的程序内容（而不是只有执行到的）
