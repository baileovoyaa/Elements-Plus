# 分离存储

已编译电路图的电路不直接存物品里，而是永久写入存档的data子目录中（`data/elements-plus/circuits/<uuid>.dat`），物品里只留引用，这样方便查找，也可以减少数据冗余。这个修改同时应用于内置元件和自定义元件。

这样复制已编译的电路图，在保留编译状态的情况下，复制的还是同一份引用，由于已编译的电路图无法修改，这没有问题。如果不保留编译状态，则会将文件中的内容写入到新的可编辑电路图物品中。

这样一来，所有的已编译电路图都会拥有一个uuid，表示其引用的电路。这个uuid显示在元件名下方。

如：

```
电路图
与门
<uuid>
规模：小
```

```
电路图
*自动开关门控制器*
作者：xxx
<uuid>
规模：小
```

存档的自定义元件不仅包含电路信息，还有元件的一系列元数据，如名称、图标、颜色、宽高、引脚分布等。另外都存有编译电路的玩家uuid（实验的发起者）。

# 命令

```
/elements-plus circuit give <元件名/uuid> [diagram|chip]  # 获取电路图（默认）或芯片
/elements-plus circuit list all  # 列出所有已编译电路
/elements-plus circuit list player <玩家>  # 列出某个玩家创建的电路
/elements-plus circuit list name <元件字符串名>  # 列出所有同名元件（内置元件用id字符串）
/elements-plus circuit list id <uuid>  # 显示对应uuid的电路图信息，不获取物品
/elements-plus circuit <recall|clean> <all|player <玩家>|name <元件字符串名>|id <uuid>>  # 列出/清理丢失（未使用）的电路（暂不用实现）
```

使用命令 `/elements-plus circuit give <元件名/uuid> [diagram|chip]` 可以获得对应元件名/uuid的电路图（`diagram`，默认）或芯片（`chip`）。uuid与元件名同名时，uuid优先。元件名有多个重复时报错，并列出所有同名元件的创建者和uuid，增加点击事件，点击可以输入 `/elements-plus circuit give <uuid> [diagram|chip]` 到聊天栏（类似原版locate命令反馈的点击事件）。

获取芯片时，内置元件统一给予小规模芯片且不写入电路 UUID：内置元件芯片只记录元件 id，同一元件的多个已编译电路等价，重名时直接取第一个；自定义元件按电路图的规模给予对应规模的芯片并记录电路 UUID，重名时列出的点击事件会带上 `chip` 参数，点击即可获取对应元件的芯片。

使用命令 `/elements-plus circuit list ...` 可以列出一系列元件，包括元件名、创建者和uuid，点击事件同上。
