---
title: 架构测例
category: 开发文档
---

测例程序要调用NOP和一系列MOV指令，使用不同的数据，并且验证没有输入、输出堵塞、MOV R3, R3等情况，以确保电路正确处理了这些

由于是固定每tick执行一条指令，因此每tick外部输入输出基本是确定的，可以使用普通时序测例的变种

PC和INS在测试时会连外部ROM，存在潜在的组合环（如INS直连PC），这个要在预检时发现。

失败测例对话框增加一列，是当前的INS对应的汇编（如MOV R0, R3）

由于输入输出较多，只需包含这些列：

```
tick PC INS 汇编 VI RI DI VO RO DO
```

不需要区分“预期输出”和“实际输出”

并且总线不需要展开每个通道信号强度

tick用白色，测试输入使用灰色，和普通测例一样

正确的输出使用绿色，错误的输出使用红色且后面加括号带绿色预期输出

对话框添加一个“复制程序”按钮，以空格分隔格式复制当前测例已经执行过的ROM内容（从开始到失败tick的程序字节，便于后续粘到ROM里手动调试）

跳转章节由于PC不是线性的，tick数和程序长度可能并不相同，所以跳转章节实验的复制按钮是复制整个测例的程序内容（而不是只有执行到的）

未引入的指令不测，因此能过后面章节的放前面章节测可以通过（但是之前章节的指令可包含，例如立即数及后面的章节可以用MOV），不依赖未定义的NOP行为
