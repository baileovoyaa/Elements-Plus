## `statusButton`

`statusButton` 是一个按钮，用于显示实验桌的状态，目前一共有四种状态：

- `idle` 空闲，未进行任何实验。
- `busy` 正在进行实验。
- `success` 实验成功（物品取出或切换实验后变为 `idle`）。
- `error` 实验失败，或预检未通过。

## 实验流程

玩家选择实验，然后点击开始实验按钮（`startExperimentButton`），如果玩家解锁的章节中包含该实验，则继续下面的流程，否则操作无效。

> 如果玩家解锁的章节不包含该实验，他仍可以暂停、停止或从暂停状态恢复，但不能开始。暂停和恢复并不会影响最终被记录完成实验的玩家

- 如果放入的物品符合预检，则开始实验流程，`statusButton` 变为 `busy` 状态。
- 如果不符合预检，按钮会变为 `error` 状态，悬停提示（Tooltip）可以查看具体原因。

实验在服务端运行，一个实验可能会进行多个tick，此时玩家可以将物品留在实验桌，只要实验桌被加载，实验就会继续进行。某个实验在某一tick该做什么，成功、失败还是继续进行，由实验本身决定。

进度条反映的是实验进度，值根据实验类型来，例如通过测例的个数与总测例的比值。

实验过程中，`startExperimentButton` 会显示为 `pause.png`，点击可以暂停实验；如果按住Shift键，按钮会显示为 `stop.png`，此时点击按钮会停止实验。

实验过程中物品被取出或替换，则实验会强制停止，`statusButton` 会变为 `idle` 状态。

实验完成后，`statusButton` 会变为 `success` 状态。该实验标记为完成，物品可能会被转化。取出物品或替换后，`statusButton` 会变为 `idle` 状态。

> 注：只有发起实验的玩家（initiator）会标记为完成。其他玩家可以暂停或从暂停状态恢复（即使解锁的章节中不包含该实验），但都不会改变“开始实验的玩家”

## 电路实验

电路实验（`CircuitExperiment`）由多个测例组成，进行实验时需要按顺序运行每个测例，一个测例运行完后再运行另一个测例。不要在一个tick中连续运行多个测例（以减轻服务器负担）。

在实现时考虑未来兼容性：

- 目前只需要实现组合逻辑测例（`CombinationalTestCase`），而未来会加入需要多个tick的测例（时序测例）。
- 目前只包含常量输入组合逻辑测例（`ConstantCombinationalTestCase`），而未来会有包含随机输入的测例（如8位加法器，65536种可能输入都测一遍并不现实）。

上述未来特性目前不需要刻意实现，但是兼容性要保留。

预检时检查：

- 检查物品是否是 **没有 `EQUIVALENT_COMPONENT`** 的电路图
- 是否包含所有需要的输入和输出标签（可以有多余的，测试时多余的输入全部设为0）
- 测例中包含的输入和输出标签都唯一对应一个元件，没有多个输入/输出元件共用标签的情况（非测例包含的输入/输出不影响），也没有把输出标签填到输入元件上这种情况
- 不存在组合环路

预检不通过要在 `statusButton` 显示为 `error` 状态，并在悬停提示显示具体原因。例如：

```
预检不通过
- 缺少输入标签：A B
- 缺少输出标签：Y
```

每执行完一个测例，如果执行成功，则将对应的 `TestCaseWidget` 的 `color` 设为绿色，并将中间文本设为 `正确`；如果执行失败，中止实验并将对应的 `TestCaseWidget` 的 `color` 设为红色，并将中间文本设为 `错误`。

全部执行完成后，实验成功。

## `ConstantCombinationalTestCase`

目前只有这一种测例类型。一个测例只运行1tick。每个测例会设置输入元件的值（与实验无关的输入元件全部置0），并在 **服务端** 进行一次组合求值，判断对应输出元件的值是否符合要求。

`ignoreAnalog` 字段表示是否忽略输出信号强度（只关心0和非0）。

- 如果 `ignoreAnalog` 为 `true`，则信号强度不被考虑在内。此时如果预期值为非0，实际值也为非0即可，而对具体信号强度没有要求。
- 如果为 `false` 则严格比较信号强度。

一旦输出不符合要求，就使实验失败，不再继续执行后续测例。`statusButton` 悬停提示写明具体测例信息。例如：

```
测试不通过
- 输入：A=0, B=1
- 预期输出：S=1, C=0
- 实际输出：S=1, C=1
```
